# 重力乐园 · 渲染操作指南

这份指南写给 J 和任何接手的人：不需要懂 Blender，复制下面的命令到「终端」里就能开始、查看、暂停、续渲和出成片。所有命令都在这台 Mac（M1 Pro，16 GB）上用 1–3 帧实测过（2026-10-24）。

---

## 0. 准备（只需确认一次）

| 项 | 位置 | 检查命令 |
|---|---|---|
| Blender 5.2 | `/Applications/Blender.app` | `/Applications/Blender.app/Contents/MacOS/Blender --version` |
| ffmpeg（出成片用） | `/Users/jgy/my_bins/ffmpeg` | `/Users/jgy/my_bins/ffmpeg -version` |
| 项目目录 | `~/Desktop/重力乐园` | `cd ~/Desktop/重力乐园` |

Blender 装在别处时，在命令前加 `BLENDER=/你的路径/Blender`；ffmpeg 同理用 `FFMPEG=...`。

以下所有命令都先进入项目目录：

```bash
cd ~/Desktop/重力乐园
```

---

## 1. 一条命令开始正式渲染（推荐档）

```bash
scripts/render.sh start
```

- 默认就是推荐档：**Cycles 64 采样 + 降噪，1920×1080，运动模糊按分镜表**，输出到 `renders/final/frame_0001.png … frame_1044.png`。
- 在后台运行，关掉终端窗口也会继续；渲染期间 Mac 不会自动睡眠（脚本内部用了 `caffeinate`）。合上笔记本盖子仍会睡眠，请插电并保持开盖。
- 已经渲好的帧会自动跳过，所以这条命令同时也是「续渲」命令。
- 正在渲染时再执行一次会被拒绝，不会重复启动。

---

## 2. 选择画质档（采样数）

实测（2026-10-24，本机，3 个代表帧 1.0 s / 26.0 s / 42.0 s 的平均，1920×1080；对比图 `renders/bench/tiers_v2.jpg`）：

| 档位 | 命令 | 实测 秒/帧 | 全片 1044 帧【估计】 | 与 128 采样的差异（PSNR / SSIM） | 肉眼观感 |
|---|---|---|---|---|---|
| EEVEE 1080p | `scripts/render.sh start --engine eevee --out renders/final_eevee` | 8.7 | 约 2.5 小时 | 20–26 dB / 0.87–0.96 | 玻璃瓶发黑、瓶里的水看不见、金属反射偏假，**不推荐** |
| Cycles 32 采样 | `scripts/render.sh start --samples 32 --out renders/final_32` | 14.4 | 约 4.2 小时 | 40–45 dB / 0.989–0.995 | 正常观看看不出区别；100% 放大时暗部和玻璃略"塑料"，可当快速成片 |
| **Cycles 64 采样（推荐，默认）** | `scripts/render.sh start` | 23.3 | 约 6.8 小时 | 41–47 dB / 0.992–0.997 | 和 128 采样放大对比几乎一致 |
| Cycles 128 采样 | `scripts/render.sh start --samples 128 --out renders/final_128` | 40.0 | 约 11.6 小时 | 基准 | 最干净，但比 64 多花约 5 小时，提升肉眼难见 |

说明：
- 时间是代表帧的实测平均，不同镜头会有 ±20% 的浮动；全片总时长是按平均值推算的估计。
- 不同档位请用不同的 `--out` 目录。同一个目录里混入不同设置的帧会被脚本拦下（避免画质前后不一致），确认无所谓时可加 `--force`。
- 试过减少光线反弹次数（漫反射 2、光泽 3、透射 8）：64 采样下反而略慢（25.3 秒/帧），画质也略降，所以没有采用。持久数据（`persistent data`）已默认开启。降低分辨率再放大不推荐，没有做。

其他可调参数：

| 参数 | 含义 | 例子 |
|---|---|---|
| `--samples N` | 采样数（Cycles）；EEVEE 下是抗锯齿采样 | `--samples 32` |
| `--engine cycles\|eevee` | 渲染器 | `--engine eevee` |
| `--percent P` | 分辨率百分比（100 = 1920×1080，50 = 960×540） | `--percent 50` |
| `--frames A-B` | 只渲第 A 到 B 帧（单帧写 `--frames 300`） | `--frames 480-575` |
| `--out 目录` | 输出目录 | `--out renders/test` |
| `--mblur auto\|off` | 运动模糊：auto = 按分镜表逐镜设置（大多数镜头 0.08–0.12，弹射一镜 0.35）；off = 全部关闭 | `--mblur off` |
| `--fg` | 在当前终端前台运行（适合试渲一两帧，看得到输出） | `--fg` |

## 3. 试渲：单帧或一小段

帧号 = 秒数 × 24 + 1（例如 20.3 秒 ≈ 第 488 帧）。

```bash
# 只渲第 488 帧（天平），前台运行，约半分钟
scripts/render.sh start --frames 488 --out renders/test --fg

# 渲 24.0–25.5 秒那一段（第 577–613 帧），64 采样，后台
scripts/render.sh start --frames 577-613 --out renders/test
```

结果在 `renders/test/frame_0488.png` 等，用「预览」打开即可。想重渲某帧，先删掉那张 PNG 再执行。

## 4. 查看进度和剩余时间

```bash
scripts/render.sh status
```

会显示：是否在渲染、使用的设置、已完成帧数 / 1044、最近 10 帧的平均秒数，以及剩余时间估计。其他目录加 `--out`，例如 `scripts/render.sh status --out renders/final_32`。

看实时日志（按 Ctrl+C 只是退出查看，不会停止渲染）：

```bash
scripts/render.sh log
```

日志文件本身在 `renders/final/render.log`。

注意：剩余时间总是按「全片 1044 帧」计算；只渲一小段（`--frames`）时这个数字偏大，看"已完成"帧数即可。实测：64 采样在本机约 26–27 秒/帧（含每帧的场景同步）。

## 5. 暂停 / 停止

```bash
scripts/render.sh stop
```

- 安全：已经完成的帧全部保留；正在渲的那一帧会作废，下次启动时自动清理。
- 脚本记录的进程号在 `renders/final/.render.pid`（第一行是后台 `caffeinate` 的 PID，Blender 是它的子进程）。万一脚本失效，可用「活动监视器」搜索 `Blender` 结束进程，效果相同。
- 不要在渲染时移动或改名 `renders/final` 目录，也不要在渲染时重建场景（见第 8 节）。

---

## 6. 续渲（睡眠、重启、断电、手动停止之后）

```bash
cd ~/Desktop/重力乐园
scripts/render.sh start
```

和开始是同一条命令：自动删除中断时留下的 0 字节或不完整的帧，然后从缺的帧继续。如果当初用的是别的档位，带上同样的参数，例如 `scripts/render.sh start --samples 32 --out renders/final_32`。

旧命令 `scripts/resume_render.sh` 仍然可用，等同于 `scripts/render.sh start`。

## 7. 出成片

全部 1044 帧完成后：

```bash
scripts/encode_final.sh                       # → renders/重力乐园_final_1080p.mp4（H.264 + AAC 320k）
scripts/encode_final.sh --prores              # 另外出 ProRes 422 HQ 母带 renders/重力乐园_final_1080p_prores.mov（体积大，适合交片或再剪辑）
scripts/encode_final.sh --in renders/final_32 # 编码其他档位目录 → renders/重力乐园_final_32_1080p.mp4
```

声音自动使用 `audio/mix/重力乐园_mix.wav`。帧不全时会提示，并在第一个缺帧处结束。

## 8. 改了东西之后：重建场景和声音

只要改过 `scripts/` 里的物理、模型、镜头或声音脚本，就要先重建（约 1 分钟），再渲染：

```bash
scripts/render.sh stop          # 如果正在渲染，先停
./scripts/run_pipeline.sh       # 物理 → 建场景 → 提取碰撞 → 合成音频
```

重建后，之前渲好的帧和新场景可能对不上：受影响的镜头需要删掉对应帧重渲（帧号 = 秒数 × 24 + 1），全局改动则换一个新的 `--out` 目录从头渲。

## 10. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 很慢，日志里看不到 `Metal` / `GPU` | GPU 没启用。日志开头应有 `GPU: [('Apple M1 Pro …', 'METAL', True)]` 和 `RENDER_SETUP cycles … device GPU`。确认用的是 `scripts/render.sh`（它会自动启用 Metal）。 |
| 内存不足、Mac 变卡、进程被系统杀掉 | 关掉其他大程序（浏览器多标签、剪辑软件）后 `scripts/render.sh start` 续渲。本场景渲染进程约占 2 GB；仍不行时可用 `--samples 32` 换目录渲。 |
| 某几帧全黑、花屏或文件很小 | 先找出可疑帧：`find renders/final -name 'frame_*.png' -size -100k`，删掉后执行 `scripts/render.sh start` 自动补渲。 |
| 提示"已经在渲染中，拒绝重复启动" | 正常保护。看进度用 `status`；确定没有在渲（例如 Mac 重启过）但仍提示时，删掉 `renders/final/.render.pid` 再启动。 |
| 提示"输出目录里已有用不同设置渲的帧" | 换一个 `--out` 目录，或确认要混用时加 `--force`。 |
| 提示"检测到另一个渲染进程" | 另一个目录的渲染还在跑，两个同时跑都会变慢。先 `stop` 那个，或确实要并行时加 `--force`。 |
| 渲到一半合盖 / 睡眠了 | 唤醒后执行 `scripts/render.sh start` 续渲即可。 |

## 【说人话】

- 开始渲染：`cd ~/Desktop/重力乐园` 然后 `scripts/render.sh start`。默认 64 采样，全片大约 7 小时（估计），可以随时停、随时续。
- 赶时间用 32 采样（约 4 小时，正常观看看不出差别）；追求极致用 128 采样（约 12 小时）。EEVEE 虽然快，但玻璃瓶会发黑，不建议。
- 看进度：`scripts/render.sh status`；停止：`scripts/render.sh stop`；停了或睡眠后再执行一次 `start` 就从断点继续。
- 渲完：`scripts/encode_final.sh` 出 MP4 成片。
